# NEWS SITE GENERATION PLATFORM
# Architecture & Development Plan
# Stack: React + TypeScript + Laravel + MySQL

==================================================
1. PRODUCT VISION
==================================================

Build a reusable platform for creating and maintaining
multiple news websites from one central codebase.

The platform must allow:

1. Create a news website project.
2. Select a theme.
3. Add/remove/reorder reusable components.
4. Configure each component visually.
5. Customize colors, typography, header, footer, etc.
6. Preview the complete website live.
7. Use demo content during preview.
8. Generate a standalone client website.
9. Deploy the generated website to shared hosting.
10. Maintain multiple client websites.
11. Release platform/component/theme updates.
12. Safely upgrade existing client websites.
13. Preserve client content and customizations.

Core principle:

    Build Once
        ↓
    Reuse
        ↓
    Customize
        ↓
    Generate
        ↓
    Deploy
        ↓
    Maintain
        ↓
    Upgrade Many Clients

==================================================
11. COMPONENT REGISTRY
==================================================

Create a central registry.

Example:

const registry = {
    hero: Hero,
    "breaking-news": BreakingNews,
    "news-grid": NewsGrid,
    "news-list": NewsList,
    advertisement: Advertisement
};

The platform should never hard-code every component
inside the builder.

The builder should discover components from metadata.


==================================================
12. COMPONENT SCHEMA
==================================================

Every component defines its configuration schema.

Example:

{
    "name": "news-grid",
    "version": "2.1.0",
    "fields": {
        "title": {
            "type": "text"
        },
        "category": {
            "type": "category"
        },
        "columns": {
            "type": "select",
            "options": [2, 3, 4]
        },
        "limit": {
            "type": "number"
        }
    }
}

The builder reads this schema and automatically
generates the settings UI.


==================================================
13. COMPONENT CONFIGURATION
==================================================

Store configuration as data.

Example:

{
    "component": "news-grid",
    "version": "2.1.0",
    "props": {
        "title": "Sports",
        "category": "sports",
        "limit": 8,
        "columns": 4
    }
}

This means changing a component's configuration
does not require modifying PHP or React source code.


==================================================
14. DATA / PRESENTATION SEPARATION
==================================================

Use:

Database

   ↓

   ↓
HTML


Example:

NewsGrid receives:

It should not know how the database works.

==================================================
51. GOLDEN RULES
==================================================

1. Build the platform once.

2. Never copy-paste the entire platform for every client.

3. Never allow clients to edit core platform code.

4. Separate content from presentation.

5. Separate theme source from theme configuration.

6. Separate client customization from platform code.

7. Version every reusable component.

8. Version every theme.

9. Maintain a platform.lock for every generated site.

10. Preview and production must use the same renderer.

11. Never generate a complete project for every builder change.

12. Generate only after the client approves the design.

13. Backup before updates.

14. Never blindly overwrite client customization.

15. Use migrations for database changes.

16. Build React assets before shared-hosting deployment.

17. Keep public pages SEO-friendly.

18. Start with one excellent theme.

19. Build reusable components before building many themes.

20. Add Rust only when it solves a real problem.

54. CORE BUSINESS PRINCIPLE
==================================================

The platform is NOT simply:

    "a news CMS"

and it is NOT simply:

    "a website generator"

It is:

    A versioned product platform for generating,
    deploying, and maintaining many independent
    news websites from one reusable codebase.

The most important engineering goal is:

    Change the platform once
            ↓
    Safely propagate the change
            ↓
    To many client websites
            ↓
    Without destroying:
        - client content
        - client configuration
        - client extensions
        - client theme overrides


==================================================
55. SUCCESS CRITERIA
==================================================

The MVP is successful when you can do this:

    1. Create a project
    2. Select Modern theme
    3. Add Hero
    4. Add News Grid
    5. Configure News Grid
    6. Reorder sections
    7. Change colors
    8. See live preview
    9. Approve design
   10. Generate project
   11. Download deployment package
   12. Deploy to shared hosting
   13. Add real client content
   14. Release a component update
   15. Upgrade the client site
   16. Verify client content/customizations remain intact

If this complete loop works reliably, the foundation
of the business is proven.
